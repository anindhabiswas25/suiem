## What works and how to see it

### Manual demo (local)

```bash
docker compose up -d --wait && pnpm i && pnpm db:migrate && pnpm db:seed && pnpm dev   # API runs the research worker inline
pnpm extension:build    # load apps/extension/.output/chrome-mv3 unpacked
```

1. **Extension request.** On x.com, a post mentioning `$NVDA` shows the toast. Click **Research**: the side panel opens. Click **Request AI research**, check the preview, then **Confirm and send**. The panel shows "Researching…". About 15–25 s later it shows the **latest brief**: summary, top risks and **Read the full brief with sources**. There is still no buy button.
2. **Web brief.** `/research/ent:nvidia` shows, in PRD §6.5 order:
   - **Overview:** the label "AI-generated by openai/gpt-oss-120b via Groq, ‹time›", "Not investment advice", data freshness and the last price with timestamp and source.
   - **Content sections:** business model, **financials table**, **valuation**, industry, competitors, latest news, risks + bear case, bull/base scenarios, sources and open questions.
   - **Actions:** follow-up questions, feedback, watchlist, thesis, and trading ("Testnet trading arrives in Sprint 5", no button).
   - Every figure row shows value, period, as-of date, kind (reported/calculated), formula and a source link (SEC filing index or Finnhub). Every claim has citation chips to its source.
3. **Follow-up.** Ask "How fast did revenue grow?". The answer cites `[s1] SEC EDGAR`. If the sources don't cover a question, the answer says so.
4. **Compare.** `/research/compare` → pick NVIDIA, Apple, TSMC → a table with sources. TSMC shows "Not available" for SEC figures (foreign filer, no US-GAAP XBRL) and says why.
5. **Watchlist.** On a research page, **Add to watchlist** (Default or another list). `/watchlist` supports multiple lists, notes, a live quote with timestamp and source, a thesis link, and research links.
6. **Thesis.** On the research page, **Create a thesis** → **Draft with AI from the brief**. This fills the form and says "Not saved yet". Edit it, pick evidence claims, then **Save thesis**. v1 is frozen with the price at that moment. **Edit** creates v2; v1 stays visible read-only in the history. Visibility stays **Only me** until you choose **My followers** or **Everyone**. Outcome reviews are added alongside and never change versions.
7. **Home** lists the latest briefs, watchlists and theses. **Help** lists the AI and data providers, the Gemini free-tier data-use note and the Finnhub free-tier label.

## Security review follow-ups (fixed this sprint)

1. **Quota bypass by refund:** failed requests refunded their daily slot even after the model had spent tokens. Now:
   - only failures before any model answer are refunded;
   - the refund uses the same day's key and never goes below zero (atomic Lua script);
   - unparseable output (`bad_output`) also counts as spent.

The automated review of one later commit (the live smoke script and Gemini fix) didn't finish in time; see `~/.claude/security/log.txt`.

## Deviations and decisions

| Item | What and why |
| --- | --- |
| Gemini model | `gemini-3.5-flash`, chosen from the live model list. `gemini-2.5-flash` is closed to new users (404). Recorded as R-02. |
| `valuation` in the brief schema | Changed from AI claims to code-filled `financialFigureSchema` rows (Finnhub values with source and as-of date), as the brief requires. Added `industryContext`, `baseCase` and `generation.provider`. |
| Excerpt in the prompt | The user's excerpt is context only, **not citable**, in its own sealed block. Citable sources are only what was retrieved. |
| Thesis reviews | A new append-only `thesis_reviews` table, so outcome notes never edit frozen versions. |
| Followers visibility | Uses the existing `follows` table; there is no UI to follow anyone until Sprint 6. |
| `GET /research/requests` | Now `user_or_device` (it was user-only in Sprint 3). The side panel needs it for polling. A device token still can't read full briefs, theses or watchlists. |
| Worker placement | The API runs the BullMQ worker in-process by default (`RESEARCH_WORKER=inline`, one Railway service). `pnpm --filter @suiem/research start` runs it standalone. |
| Finnhub news links | Finnhub returns `finnhub.io/api/news?id=…` redirect URLs, which we show as returned. For NVDA the feed includes general market stories, so the model sometimes cites market news (R-10). |
| Valuation "as of" | Finnhub metrics carry no timestamp, so the as-of date is the retrieval date, labelled "As published by Finnhub". |
| Quota for follow-ups and drafts | Separate daily counters: questions get 3× the brief limit, drafts 1×. |
